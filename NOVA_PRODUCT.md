# NOVA Product

## Product Positioning

NOVA is an AI-first life agent.

Core promise:

> Tell NOVA what you need. NOVA figures out how to get it done.

NOVA is not a generic chatbot. The product turns natural user needs into structured tasks, asks only necessary questions, selects safe tools, executes approved actions, and helps the user reach a useful outcome.

## User Problem

People often know what they need but do not want to search across apps, websites, service providers, reviews, prices, forms, calendars, and messages.

NOVA should become the layer between intent and completion:

```text
User
Intent
Plan
Tools
Actions
Result
```

## Primary Metric

The main metric is not messages or chat sessions.

Primary metric:

> Useful things NOVA helped the user accomplish.

Supporting metrics:

- Tasks created
- Tasks completed
- Task completion rate
- Successful tool actions
- Time from prompt to task plan
- Time from task plan to completion
- Repeat usage
- AI cost per successful task

## MVP Product Scope

The MVP must prove one thing: a user can naturally express a need and NOVA can turn it into a clear, trackable task.

MVP includes:

- Signup, login, logout, profile
- Text-first AI chat
- Voice and image architecture placeholders with clear interfaces
- Intent detection
- Missing information questions
- Task generation
- Task list, detail, update, complete, cancel
- Controlled memory for basic preferences
- Reminders
- Basic service categories
- Provider listing and details from seeded or explicitly marked demo data
- Request flow with confirmation before medium-risk actions

MVP excludes:

- Payments
- Full national marketplace
- Complex provider recommendation engine
- Universal shopping
- Full travel booking
- Enterprise features
- Large integration catalog

## Differentiation

NOVA should differentiate through:

- Execution, not conversation volume
- Multilingual understanding across French, English, Arabic, Tunisian dialect, and Arabizi
- Controlled personal and household memory
- Transparent task states and event history
- Human approval for consequential actions
- International architecture from day one
- Local service execution as a long-term moat

## Product Principles

- First request must be possible within seconds
- Ask only questions needed to proceed
- Never invent provider ratings, availability, prices, or verification
- Show what NOVA understood before taking consequential action
- Do not expose model chain-of-thought
- Make memory visible, useful, deletable, and minimized
- Make every task state understandable to a non-technical user

## Success Criteria

The MVP succeeds when a new user can:

1. Open NOVA
2. Understand immediately what it does
3. Write a natural request
4. Get a useful interpretation
5. Answer one missing-info question if needed
6. See a task created
7. Understand the next step
8. Approve or reject available actions
9. Track the task
10. Complete or cancel it cleanly
