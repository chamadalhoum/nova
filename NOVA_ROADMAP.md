# NOVA Roadmap

## Phase 0: Research and Validation

Goal: validate the product thesis before marketplace expansion.

Deliverables:

- Product vision
- Competitor research
- White-space definition
- MVP plan
- Initial UX flows
- Technical architecture
- Intent test dataset

Exit criteria:

- Clear MVP scope
- Clear first market assumptions
- No unresolved architectural blocker

## Phase 1: MVP AI Life Agent

Goal: prove natural request to structured task completion.

Includes:

- Authentication
- Profile
- Text AI chat
- Intent classification
- Dynamic questions
- Task generation
- Task tracking
- Controlled memory
- Reminders
- Basic provider discovery using real or clearly marked demo data
- Web and mobile foundations

Exit criteria:

- User can submit first request in seconds
- NOVA can create a task from a natural prompt
- User can complete or cancel the task
- AI does not invent provider data
- Confirmation gates work

## Phase 2: Service Agent

Goal: make home and local service requests useful.

Includes:

- Better service categories
- Provider onboarding/admin tooling
- Availability model
- Quote/request flow
- Trust and verification metadata
- Reviews once real jobs exist
- Support/dispute workflow

Exit criteria:

- Real provider supply in one or more categories
- Measurable request-to-booking conversion
- Transparent trust signals

## Phase 3: Home Passport

Goal: contextualize household tasks.

Includes:

- Homes
- Assets
- Photos/documents
- Warranty dates
- Maintenance and repair history
- AI use of asset context

Exit criteria:

- Home-related prompts become faster and more accurate
- Users understand and control stored asset data

## Phase 4: Advanced Voice and Vision

Goal: make voice and image natural primary inputs.

Includes:

- Production speech-to-text
- Voice UX polish
- Vision provider integration
- Image confidence labels
- Multilingual voice testing

Exit criteria:

- Voice and image requests create useful tasks reliably
- No unsupported diagnostic certainty

## Phase 5: Tools and Integrations

Goal: extend execution through integrations.

Potential tools:

- Calendar
- Email
- Maps
- Search
- Booking
- Notifications
- Shopping
- Weather

Exit criteria:

- Tool permission model handles read-only, low, medium, and high-risk actions
- Tool failures are safe and explainable

## Phase 6: Payments

Goal: support transactions only after trust and confirmation flows are mature.

Includes:

- Payment provider abstraction
- Explicit confirmation UX
- Receipts
- Refund/dispute flow
- Commission support

Exit criteria:

- No transaction can happen without explicit user approval
- Payment audit trail is complete

## Phase 7: International Expansion

Goal: expand by configuration, not rewrites.

Includes:

- Country configuration
- Local provider rails
- Currency and tax/regulatory support
- Locale-specific onboarding
- Market-specific integrations

Exit criteria:

- New country can be added without core architecture changes
